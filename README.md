# Portfolio — Esther Almendros

[![Deploy](https://github.com/estheralmendros/portfolio/actions/workflows/deploy.yml/badge.svg)](https://github.com/estheralmendros/portfolio/actions/workflows/deploy.yml)

A static personal portfolio at **https://estheralmendros.github.io/portfolio/**, generated by [Astro](https://astro.build) from the JSON files in [`content/`](content/), plus a private, bookmark-only admin panel at **`/portfolio/admin/`** where the owner edits every section (profile, projects, skills, certifications, experience), uploads images and the CV, and previews changes, using a GitHub fine-grained token. Every admin save is one commit to `main`; GitHub Actions verifies, builds and redeploys the site to GitHub Pages.

## Setup

### One-time prerequisites (not automated)

1. **The repository `estheralmendros/portfolio` is public.** GitHub Pages on a free personal account requires a public repository.
2. **Settings › Pages › Source = GitHub Actions.**
3. **The `github-pages` environment allows deployments from `main`** (the default; check Settings › Environments › github-pages › Deployment branches).
4. **The owner creates a fine-grained token** (only needed for the admin):
   - GitHub › Settings › Developer settings › Personal access tokens › Fine-grained tokens › Generate new token
   - Repository access: **only `estheralmendros/portfolio`**
   - Permissions: **Contents → Read and write** (Metadata: Read is added automatically)
   - Optional: **Actions → Read-only**, for the admin's deploy status badge. Without it the badge shows "Status unknown" (saves still work)
   - Expiration: e.g. **90 days**

### Local development

Requires Node.js 22 or later.

```bash
npm ci
npx playwright install chromium   # once, for the e2e tests
npm run dev                       # http://localhost:4321/portfolio/
```

## Usage

### Editing content

All public content lives in `content/*.json` (`profile`, `projects`, `skills`, `certifications`, `experience`). Array order is display order. Optional fields are **omitted** when empty (never `""` or `null`, except `experience.end`, where `null` means "Present"). The schemas are in [`src/content/schema.ts`](src/content/schema.ts); `npm run build` fails with a file-and-path message (e.g. `content/projects.json › [1].date: Expected YYYY-MM`) on any violation.

Images and files referenced as `/path` live in `public/` (e.g. `/images/portfolio.png` → `public/images/portfolio.png`). Write paths **without** the `/portfolio` base; it is added automatically. Images uploaded through the admin live in `src/assets/uploads/` and are referenced without a leading slash (e.g. `src/assets/uploads/projects/portfolio-a1b2c3.webp`); a reference to a missing upload fails the build.

### Admin (`/portfolio/admin/`)

1. Open `https://estheralmendros.github.io/portfolio/admin/` (it is not linked anywhere; bookmark it).
2. Paste the fine-grained token and log in. The token is kept only in this tab (`sessionStorage`).
3. Use the header tabs **Profile · Projects · Skills · Certifications · Experience**. Each list has **+ New**, **Edit** and **Delete**; the profile is a single form. Ids are derived from the title/name (experience: role + organization) and can't change after creation. Duplicate ids and duplicate skill names are rejected; a new skill goes to the top of its category. On experience, **Present** saves `end: null`.
4. Each save is exactly one commit to `main`, e.g. `content(skills): add "Go"`, `content(experience): delete "Engineer @ Acme"`, `content(profile): update profile`. The site updates after the next deploy (a few minutes).

**Reorder.** Every list has ↑ / ↓ buttons (skills move only within their category). Moves stay local until **Save order**, which makes one commit `content(<section>): reorder`; **Discard** restores the saved order. Edit, Delete and New are disabled while an order change is pending.

**Images** (project image, profile photo, certification badge). **Upload image** accepts JPG, PNG or WebP (badges also SVG), up to 20 MB. The image is resized in the browser to at most 1600 px on its longest side (never upscaled) and must be 2 MB or less afterwards. SVG badges are always converted to a 320 px PNG, so no SVG file is ever committed; an SVG that can't be read safely (e.g. with `<foreignObject>`) is rejected with "Use a PNG instead". The file is committed together with the JSON in the same commit (`… (+image)`), under `src/assets/uploads/<section>/<id>-<6 hex>.<ext>`; Astro optimizes it at build time, so it appears on the site only after the deploy. Upload paths can't be typed by hand: use **Upload image**, or type an `https://` URL or a `/path` in `public/` under "or use a URL / path". Replaced or removed images stay in the repository.

**CV.** **Upload CV (PDF)** accepts a real PDF (it must start with `%PDF-`) of 5 MB or less. It is committed as `public/uploads/cv.pdf` with `cvUrl: "/uploads/cv.pdf?v=<id>"` (the query defeats caches) in one commit (`(+cv)`, or `(+image, +cv)` with a new photo). **Remove CV** (with **Undo** until you save) deletes the uploaded file in the same commit (`(-cv)`); for an external URL or another `/path` only the link is removed. Caveat: earlier CV versions stay in the public repository's git history; removing them requires a history rewrite.

**Preview.** Every form shows a live preview built with the same components as the public site (side by side from 1024 px, an Edit / Preview tab switch below). A newly selected image shows immediately; skill icons appear only after the deploy (the preview shows initials). "Fix errors to save" means the form has errors; the preview still renders what it can.

**Deploy status.** After each save the header badge follows the deploy workflow run of that commit: **Deploying…**, **Live** (link to the site), **Failed** (link to the run), **Replaced by a newer deploy** (a later save superseded it) or **Status unknown** (no Actions permission on the token, or it took too long; link to the Actions page). A failed deploy is also reported by GitHub's usual workflow-failure email.

If the admin reports "Content changed elsewhere", reload to get the latest version; nothing was overwritten. Switching tabs with unsaved changes asks before discarding them.

### Public site

The Projects section has a technology filter (chips above the grids, single-select). It is progressive enhancement: without JavaScript all projects are shown and the chips are hidden.

### Commands

| Command | What it does |
|---|---|
| `npm run dev` | Astro dev server (no CSP in dev) |
| `npm run build` | Real `content/` → `dist/` |
| `npm run build:test` | Fixture `tests/fixtures/content/` → `dist-test/` |
| `npm run preview` | Serve the last build (`astro preview`) |
| `npm run lint` | ESLint (flat config) |
| `npm run typecheck` | `astro check && tsc --noEmit` |
| `npm test` | Vitest unit (node) + component (jsdom) tests |
| `npm run test:smoke` | Structural checks over `dist/` (`SMOKE_DIR=dist-test` for the fixture build) |
| `npm run test:e2e` | Playwright against `dist-test/` (run `npm run build:test` first) |
| `make all` | Everything CI runs, in CI order |

### Deployment

`.github/workflows/deploy.yml` runs on every push to `main`, on manual dispatch and weekly. The `verify` job runs lint, typecheck, unit/component tests, the real build + smoke check, the fixture build + smoke check, and the e2e suite; the `deploy` job publishes `dist/` to GitHub Pages only if all of them pass.

## Security

The admin keeps the token in `sessionStorage`, which is scoped per **origin**. `https://estheralmendros.github.io` is shared by every GitHub Pages project site of the account and by the public portfolio pages, so any script running on that origin in the same tab could read the token. This is an accepted, documented risk, mitigated as follows:

- **Owner rule: no site published under `estheralmendros.github.io` may load third-party or analytics scripts while this admin uses `sessionStorage`.** This applies to every repository of the account that publishes to GitHub Pages, not only this one. Revisit it by moving the portfolio to a custom domain (its own origin).
- Every public page and the admin page carry a strict Content-Security-Policy meta tag (`script-src 'self'`, no inline scripts, no third-party scripts, fonts or stylesheets). The policy is emitted in production builds only (`astro dev` needs inline styles and a websocket); it is verified on the built output by the smoke and e2e tests.
- Markdown in project descriptions is rendered with raw HTML escaped and link/image URLs protocol-filtered (`javascript:`, `data:`, `//host` and similar are dropped).
- The token is minimal: one repository, Contents read/write (plus optional Actions read-only), ~90-day expiry, instantly revocable in GitHub.
- Uploaded SVGs are rasterized to PNG in the browser (loaded as an image, where scripts and external resources are inert), so no SVG that could run script on the shared origin is ever published.
- `frame-ancestors` cannot be set (meta CSP ignores it and GitHub Pages does not allow custom headers).

### Schema changes

Tightening a schema without migrating `content/` in the same commit fails the build and disables admin editing (the admin refuses to edit an invalid remote file). Always migrate content together with schema changes.
